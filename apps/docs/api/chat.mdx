## POST /api/chat

The backend for Blue Chat. Streaming SSE endpoint — returns a `text/event-stream`
response. Inference runs on the [Virtuals](https://compute.virtuals.io) gateway.

<Note>
There is no API key for this endpoint. It is not a raw public LLM API — it is the
Blue Chat backend. A connected wallet is passed as `address` in the body and is
metered against its BLUE credit balance server-side (the client-sent `tier` is not
trusted). Requests with no `address` are treated as guests and cannot use paid tools.
</Note>

### Request

```bash
curl -X POST https://blueagent.dev/api/chat \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [
      { "role": "user", "content": "How do I deploy an ERC-20 on Base?" }
    ],
    "tier": "pro",
    "address": "0xYourConnectedWallet"
  }'
```

### Body

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `messages` | array | required | Message history (`role` + `content`) |
| `tier` | string | `"pro"` | `"fast"` \| `"pro"` \| `"max"` — sets the output-token budget and credit cost |
| `address` | string | — | Connected wallet `0x…`. Drives credit metering. Omit for a guest session. |

### Model

Every tier currently routes to the Virtuals default model
(`VIRTUALS_CHAT_MODEL`, e.g. `anthropic-claude-sonnet-5`). The `tier` sets the
output-token budget, not a different provider model.

### Response

Server-sent events stream. Text arrives as delta chunks, terminated by
`data: [DONE]`:

```
data: {"type":"content_block_delta","delta":{"text":"Hello"}}
data: [DONE]
```
